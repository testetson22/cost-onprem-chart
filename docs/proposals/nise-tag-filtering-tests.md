# Proposal: Fix NISE Tag Generation for Performance Tests

**Status**: Proposed  
**Author**: Performance Testing Team  
**Date**: 2026-05-29  
**Related Test**: `test_perf_api_006_tag_filtering[10]`

## Summary

The `test_perf_api_006_tag_filtering` test validates API latency when filtering by N tags. The test variants for 1 and 5 tags work correctly, but the 10-tag variant consistently fails because NISE-generated labels are not fully flowing through to the Koku tags API.

## Current State

### What Works
- Tag filtering tests with 1 and 5 tags pass
- The `labeled_nise_source` fixture successfully:
  - Registers a source
  - Generates NISE YAML with pod labels
  - Uploads data to ingress
  - Waits for processing
  - Enables discovered tags

### What Doesn't Work
- Only ~6-9 of the 10+ generated labels appear in the tags API
- Some labels consistently appear (e.g., `app`, `tier`, `cost`)
- Other labels consistently fail to appear (e.g., `env`, `team`, `ver`, `area`, `svc`, `part`)
- The pattern is not based on:
  - Label string length (shortened labels also fail)
  - Reserved words (arbitrary names like `tagone`, `tagtwo` also fail)
  - Position in the labels string
  - Label value content

## Investigation Summary

### Attempted Fixes

1. **Added `label_` prefix** (required by NISE) - Partial success
2. **Shortened label keys** to avoid length limits - No improvement
3. **Used arbitrary names** (NATO phonetic) - All failed
4. **Fixed YAML indentation** for node section - No improvement
5. **Added tag discovery polling** (120s wait) - Tags never appeared

### Key Observations

1. **Processing completes instantly** (`elapsed=0.0s`) suggesting summarization isn't running
2. **Some labels work, others don't** from the same labels string
3. **Tags that work may be from existing cluster data**, not our NISE uploads
4. The issue appears to be in how NISE generates CSVs or how Koku processes pod labels

## Proposed Investigation Path

### Phase 1: NISE CSV Analysis
- [ ] Inspect actual CSV files generated by NISE
- [ ] Verify all labels are present in the `pod_labels` column
- [ ] Compare working templates' CSV output with our generated output

### Phase 2: Koku Processing Analysis
- [ ] Trace label flow from CSV → database → tags API
- [ ] Check if there's a label count or length limit in Koku
- [ ] Verify summarization tasks are running and discovering labels

### Phase 3: Alternative Approaches
- [ ] Use pre-existing NISE templates that have working labels
- [ ] Query tags directly from database instead of API
- [ ] Create labels via Koku internal API if available

## Workaround

The `tag_count=10` variant is currently skipped. Tests with 1 and 5 tags continue to validate the tag filtering performance characteristic, which is the primary goal of PERF-API-006.
